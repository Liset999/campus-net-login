# campus-net-login

一个 Windows 优先的校园网自动认证工具。

目标是让用户只需要选择学校或填写 SSID、学号、密码和运营商（如果学校要求），程序就能在连接校园 Wi-Fi 后自动判断网络状态、发现认证门户、执行学校适配器并验证真实外网连通性。

## 当前阶段

当前 MVP 已包含本地前端、Node 本地服务、网络诊断和南邮认证适配器。前端会采集：

- 当前 Wi-Fi SSID 和网络接口状态
- IPv4、默认网关、DNS 和默认路由
- WinHTTP、Windows 用户代理、PAC 和环境变量代理
- 常见代理/TUN 进程
- 直连与普通代理路径的 HTTP 探测结果

MVP 不修改系统代理、关闭 VPN/TUN 或重启网卡。用户点击“自动登录”后，服务只向南邮认证门户提交本次请求，普通互联网流量继续走用户自己的 Clash。

## 运行诊断器

在 PowerShell 中从仓库根目录运行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\diagnose.ps1 -TargetSsid "你的校园网 SSID"
```

诊断结果写入 `diagnostics/latest.json`。该目录已被 Git 忽略，不会被提交。

不需要在命令行输入密码。诊断结果也不会记录密码、Cookie、Authorization 头或带查询参数的完整门户 URL。

## 设计

```text
SSID → DHCP/网关 → 代理/TUN 检查 → HTTP 门户探测
                                   ↓
                   已认证 / 门户可达 / 网络失败
                                   ↓
                         学校登录适配器
                                   ↓
                         真实外网验证
```

通用核心负责网络状态、门户发现、重试、日志和成功验证；学校适配器负责门户地址、登录方法、字段名、运营商值、动态 token 或签名以及成功判据。

项目自动化的是用户自己的授权登录流程，不绕过校园网策略、不破解验证码、不共享账号，也不把凭据发送到项目作者或中央服务器。

## 规划中的适配器类型

- 普通 HTML 表单
- 需要运营商字段的门户
- 需要 Cookie、CSRF 或动态 token 的门户
- 仅支持浏览器交互的门户
- 学校自建或厂商协议适配器

如果门户包含验证码、二次认证或学校明确禁止自动化的步骤，程序应回退到浏览器辅助流程。

## 开发路线

1. 用诊断器确认 DHCP、代理、TUN、DNS 和门户重定向分别处于什么状态。
2. 为第一所学校实现浏览器辅助或最小登录适配器。
3. 使用 Windows Credential Manager 保存凭据，日志默认脱敏。
4. 增加连接指定 SSID 后的后台检测、托盘界面和自动重试。
5. 收集多个学校的适配器后，再抽象稳定的公共配置格式。

## Proxy coexistence

Clash Verge、Meta TUN 或其他代理可以保持开启。登录器不应要求用户全局关闭代理，因为代理可能是访问其他互联网服务所必需的。

学校适配器需要明确标注门户域名、网关地址和必要的校园 DNS 路径。认证请求按适配器使用直连或 Clash 的 DIRECT 规则；普通互联网流量继续使用用户原有代理。适配器不得静默修改全局代理配置。

## 运行前端 MVP

最简单的方式是双击仓库根目录的start-campus-link.cmd。也可以在 PowerShell 中运行：

1. 进入 D:\Warehouse\campus-net-login
2. 执行 .\scripts\start-mvp.ps1
3. 浏览器会自动打开本机 MVP 页面

页面当前支持：

- 填写学校 Wi-Fi、学号、密码和运营商
- 保持 Clash/Meta 开启并运行本机网络诊断
- 发现南邮门户后打开认证页
- 使用南邮 ePortal 入口提交一次登录请求
- 展示 SSID、DHCP、网关、代理、直连和代理探测结果

密码只在本次请求的内存中使用，不写入浏览器存储、日志或 Git。前端服务只监听本机 127.0.0.1。




## 测试 MVP

### 1. 先测网络检测（不填账号密码）

1. 连接学校 Wi-Fi。当前南邮测试目标是 `106_5G`。
2. 保持 Clash Verge / Meta 按日常方式开启。
3. 双击仓库根目录的 `start-campus-link.cmd`。它会自动找空闲端口并打开本地页面；如果页面已经打开，也可以访问启动器显示的 `http://127.0.0.1:<端口>/`。
4. 确认 Wi-Fi 名称是 `106_5G`，直接点击“检测并连接”。

右侧“网络现场”出现以下信息，就说明诊断链路正常：实际 SSID、IPv4 / DHCP、默认网关、代理路径、直连探测和代理探测。当前实机预期是 SSID `106_5G`、DHCP `Enabled`、网关 `10.161.255.254`、Clash 已开启；探测结果显示 `200 OK`。

### 2. 再测自动登录

1. 在“学号”填写自己的学号。
2. 选择运营商：校园网保持默认；中国移动选 `@cmcc`；中国电信选 `@njxy`；学校给了其他后缀时选“自定义后缀”。
3. 填写自己的密码。
4. 点击“自动登录”。
5. 页面显示“登录成功”后，再打开一个普通互联网网站，确认不会继续跳回校园网认证页。

密码不会写入浏览器存储、活动记录或 Git。登录失败时先检查运营商后缀，再点击“打开认证页”观察门户页面返回的提示。

### 3. 常见结果怎么判断

- “还没有连上目标 Wi-Fi”：电脑当前真实 SSID 不是表单里的 SSID。
- IPv4 或默认网关为空：Wi-Fi 尚未拿到 DHCP 租约，先断开再重连该 Wi-Fi。
- 直连失败、代理成功：Clash 本身可用，但校园门户或网关可能还需要适配 DIRECT 路径。
- 门户能打开但登录失败：检查学号、密码和运营商后缀；不要重复提交过期页面。
- 页面打不开：重新双击 `start-campus-link.cmd`，不要手动猜端口；启动器会自动选择可用端口。
